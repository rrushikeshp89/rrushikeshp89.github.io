## Reader personas (ux-researcher-designer)

These are hypotheses. The skill's persona script needs interview data, and there is none.

1. **Technical recruiter, 30-second skim.** Screens many fresher profiles against a job description. Wants to know the role, matching stack keywords, location and availability, whether the work is real, and how to make contact or get the résumé.
   → Needs: role and stack in the hero, location, a résumé link in the header, an email CTA, and keywords as plain text.
2. **Engineering manager, 3–5 minute depth check.** Deciding whether to interview. Wants to know whether the code is real and runnable, whether the numbers are backed, how auth, data integrity and testing are handled, and whether he knows his limits.
   → Needs: source and live links, receipts with proof, case studies, and honest limitations.

Heuristic review of the section order: Work comes before Experience, which is right for a fresher because the projects are the strongest evidence. Two additions: **Résumé** in the header, and a hero line "Based in Bengaluru, open to Software Developer roles".

## Architecture decisions (senior-architect)

- **ADR-001 (hosting superseded by ADR-029) Static Next.js App Router on Vercel.** Next.js 16.4.5, React 19.3, every route prerendered (`○ Static`). The scaffold's defaults are kept: `cacheComponents`, `partialPrefetching`, and Turbopack with `@tailwindcss/turbopack`. No database and no API.
- **ADR-002 Content is typed TS objects validated by Zod, not MDX.** `src/content/schema.ts` defines the model and `facts.ts` calls `factsSchema.parse()` at module load. This was verified: an invalid email in `facts.ts` makes `next build` exit 1 with a ZodError. Types come from `z.infer`, so content and types cannot drift.
- **ADR-003 Tailwind v4 over CSS-variable tokens.** `src/styles/tokens.css` holds both palettes, and `globals.css` maps them into `@theme inline` (`bg-paper`, `text-ink`, `text-accent`, and so on).
- **ADR-004 Theme without flash.** A hand-written inline `<head>` script (`src/lib/theme-script.ts`) applies a stored `light`/`dark` choice before paint. With no stored choice, CSS follows `prefers-color-scheme`. next-themes is not used. Covered by `tests/e2e/theme.spec.ts`.
- **ADR-005 (delivery superseded by ADR-029) CSP: strict everywhere except inline scripts.** The first attempt, `script-src 'self' 'sha256-<theme script>'`, was tested and failed. A statically generated App Router page carries inline RSC payload scripts (`self.__next_f.push`). Next.js cannot nonce these on a static page, because there is no request at build time, and they cannot be hashed before the build. Playwright recorded 8 blocked scripts.
  - Decision: `script-src 'self' 'unsafe-inline'`. External chunks are still pinned with SRI (`experimental.sri`, sha256).
  - Everything else stays strict: `default-src 'self'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`, `upgrade-insecure-requests`, plus nosniff, `X-Frame-Options: DENY`, Referrer-Policy, Permissions-Policy, HSTS and COOP.
  - Why the risk is acceptable: there are no third-party scripts, no user-generated content and no forms.
  - The alternative was a nonce CSP, which would make every page dynamic. That was rejected for performance.
  - `style-src` allows `'unsafe-inline'` because Radix positions popovers with inline styles.
- **ADR-006 Client islands only.** ThemeToggle, Receipt (Radix Popover), RoleSwitch (Radix ToggleGroup) and CountUp are the only `"use client"` components. Everything else is a Server Component.
- **ADR-007 Contact by `mailto:` plus LinkedIn and GitHub.** There is no form and no Server Action, so there are no secrets, no spam surface and nothing to rate-limit.
- **ADR-008 (mechanism superseded by ADR-029) Résumé.** A static PDF in `public/`, with a `/resume` redirect in `next.config.ts`. Phase 6.
- **ADR-009 Testing.**
  - Vitest with jsdom and Testing Library for unit tests.
  - Playwright with `@axe-core/playwright` against `next start` on port 4310. Ports 3023–3222 fall inside a Windows-reserved range on the dev machine.
  - The axe matrix covers every route in light and dark at 1280 px and 375 px, using the WCAG 2.0/2.1/2.2 A and AA tags plus best-practice.
  - Lighthouse CI is added in Phase 3.
- **ADR-010 No analytics; Node 24 LTS.** `.nvmrc` pins 24 for CI and Vercel, and `engines` requires Node 22 or later. Local development ran on Node 25.6.1.
- **ADR-011 Theme toggle state lives in the DOM, not React.** The toggle renders both labels and icons, and CSS (`[data-theme-only]`) shows the one that matches the effective theme. Server HTML and the first client render are therefore identical: no hydration mismatch and no label flicker. The hidden label is `display: none`, so it is also dropped from the accessible name. Clicking reads the effective theme, stores the opposite, and syncs `<meta name="theme-color">`. This fixes the low finding from the Phase 1 review.
- **ADR-012 (superseded by ADR-020) Slips are modal Radix popovers.** The brief asks popovers to trap and restore focus, so `Popover.Root` is `modal`: focus is trapped while open, Esc and the close button return focus to the trigger, and the rest of the page is hidden from assistive tech until it closes. Every slip has a visible title wired up through `aria-labelledby`.
- **ADR-013 Header is sticky from 768 px up, not on phones.** On a phone the header needs two rows (name and toggle, then the four anchors). Kept sticky, it would cover about an eighth of a 375 × 812 screen. It scrolls away instead; the hero CTAs and the Contact section repeat every action it holds. mobile-design's thumb-zone guidance put the primary CTAs full width and 48 px tall on phones.
- **ADR-014 Lighthouse runs through its Node API in Playwright's Chromium.** `@lhci/cli` uses chrome-launcher, which failed on this Windows machine with `spawn UNKNOWN`, with or without the sandbox. `scripts/lighthouse.mjs` starts `next start`, takes the median of 5 mobile runs per route, writes HTML reports to `.lighthouseci/`, and fails below Performance 95, Accessibility 100, Best Practices 95, SEO 100, or above LCP 2.0 s or CLS 0.02. Total Blocking Time is reported but not gated: it measures React and Next.js hydration on a 4×-throttled CPU, it is already weighted inside the performance score, and INP (the brief's target) can only be measured in the field.
- **ADR-015 JS budget counts what modern browsers download.** `scripts/check-bundle.mjs` sums gzipped `<script>` files referenced by the built HTML and skips `noModule` polyfills (38.7 kB of core-js that only browsers without ES modules fetch). The budget applies to `/`; `/design` is reported for information.
- **ADR-016 Facts drive optional UI.** The résumé link (header and Contact) and the "What this doesn't do yet" line render only once their facts are confirmed, so no unconfirmed fact or empty link ever reaches the page. An e2e test asserts that no `TODO(confirm)` text, `tel:` link or phone-number pattern is in the HTML, and that every number on the page appears in `facts.ts`.
- **ADR-017 Static font cuts, not the optical-size variable font.** Newsreader with its `opsz` axis came as two variable files of 132 kB (upright) and 147 kB (italic), both preloaded. On a throttled mobile run they competed with the JS, and Performance dropped as low as 88. Headings use one weight (500), so the site now loads static Newsreader 500 upright (24 kB, preloaded) and italic (not preloaded: it is only used for section titles below the fold), plus Plex Sans variable (40 kB) and Plex Mono 400/500 (10 kB each). The home page now references 84 kB of fonts instead of about 330 kB. Trade-off: no optical-size adjustment at display sizes.
- **ADR-018 Hero flow lines: static art from a real simulation, approved by the owner.** `tools/flow-lines/generate.py` runs fluidsim's 2D Navier-Stokes solver (128², ν = 1e-3, seeded noise decaying to t = 12) and traces evenly spaced streamlines through the final velocity field into `public/flow-lines.svg` (82 lines, 24.4 kB, 4.4 kB gzipped). The site uses it as a CSS `mask-image` over `--secondary` at 14% (light) and 20% (dark) opacity, fading at both edges. Checked against the brief's gate for optional effects:
  - **Off the critical path:** the image is a CSS mask, so it is never preloaded, never blocks render, and is not an LCP candidate. Added JavaScript: 0 kB.
  - **Off where it would cost or distract:** `display: none` below 768 px (no request is made, which an e2e test checks) and under `prefers-reduced-motion: reduce`. The art is static, but the brief's rule is applied literally. CSS has no reliable low-power signal (`prefers-reduced-data` is unsupported in Chrome), so the small-screen rule stands in for it.
  - **Complete without it:** with the art off, the page is exactly the Phase 3 page.
  - **Decorative only:** `aria-hidden="true"` and empty. Text contrast still passes axe in both themes.
  - **Gates:** Lighthouse mobile is unchanged, because its 412 px viewport never loads the art. On desktop, with the SVG allowed vs blocked: Performance 100 vs 100, LCP 255 ms vs 256 ms, TBT 0 vs 0, CLS 0.000 vs 0.000, and 5.3 kB transferred.
  - **Regenerate** (any Python 3.12+): `python -m venv .venv`, `pip install -r tools/flow-lines/requirements.txt`, `python tools/flow-lines/generate.py`.
- **ADR-019 (reverted) Scroll stroke from Skiper UI (skiper19).** Added at the owner's request, then removed at the owner's request after review: the component, its CSS, the `--stroke-highlight` token and its contrast pairs, the footer credit and its e2e spec are all gone. The sticky-margin fix below is kept. The original record follows.
  - **What it is:** Skiper's component is an SVG path whose drawn length follows scroll progress, driven by framer-motion (`useScroll`, `useTransform`, `motion.path`). Installing it through `shadcn add` would have run `shadcn init`, which rewrites `globals.css` and adds config. It would also have added roughly 30–45 kB of gzipped JavaScript to a home route at 135.9 kB, over the 150 kB budget.
  - **What was done instead:** the site uses Skiper's exact path with a CSS scroll-driven animation (`view-timeline` on `#work`, `animation-range: contain`), which adds 0 kB of JavaScript. Browsers without scroll timelines, and visitors who reduce motion, see it fully drawn.
  - **Placement:** the first attempt, behind the hero, read as a knot, and most of it drew while the hero was already scrolling off screen. It now sits in the sticky margin of Selected work and draws from 0% to 100% as the reader moves through the three projects, so it works as a reading-progress mark. It never passes behind text, and its `--stroke-highlight` colour is still contrast-tested against `ink` and `ink-muted`. It is hidden below the `lg` breakpoint, where there is no margin column.
  - **Licence:** the free licence requires attribution, so the footer credits Skiper UI (stored in `facts.site.credits`) and the component carries a source comment. Skiper's own credit to comgio.ai is kept in that comment.
  - **Side fix:** the margin block (title, note, aside) is now sticky as a unit. Before, only the title was sticky, and on long sections it slid over its own note.
  - **Measured:** JS on `/` is still 135.9 kB. Lighthouse mobile scored 89, 96 and 98 across three local runs (the 89 is machine noise: phones never render the stroke and the JavaScript is unchanged). Desktop scored Performance 100, LCP 267 ms, CLS 0.000, TBT 47 ms. 73 e2e tests pass, including drawing progress, reduced motion, phone hiding and the credit link.

- **ADR-020 Receipts use the native modal `<dialog>`, not Radix Popover.** Radix Popover (with its positioning, focus and scroll-lock layers) cost about 23 kB gzipped: `/design` was 159 kB against 136 kB for `/`. Putting it on the home page alongside the role switch would have broken the 150 kB budget. The native `showModal()` dialog gives the behaviour the brief asks for at no library cost:
  - **Keyboard:** opens on click, Enter or Space. Focus moves inside and the rest of the page is inert, so focus cannot reach it. Esc and the Close button dismiss it, and focus returns to the number.
  - **Backdrop:** clicking it dismisses the slip where `closedby="any"` is supported.
  - **Placement:** the dialog is portalled to `<body>`, because a dialog cannot sit inside the hero sentence's `<p>`. On wide screens CSS anchor positioning opens it next to its number and flips it to fit; elsewhere it is centred. The UA `max-height` is removed so the flips work instead of the slip being squeezed.
  - Radix was removed from the project, and `/design` now shows the same Receipt component. Without JavaScript the trigger does nothing, but the number and its label stay visible.
- **ADR-021 Every metric is a receipt; count-up is decorative.** There are 12 receipts: 4 in the hero sentence, 4 Grove numerals, 3 Stockroom numerals and the 15% in the Experience margin. Each trigger's accessible name is "45 tables, show source"; the moving digits are `aria-hidden`.
  - **CountUp:** numbers that start below the fold count up the first time they are 60% visible (900 ms, ease-out). A number already on screen at load does not animate, and none animate under reduced motion. The server HTML has the final values. The width is reserved in `ch` and digits are left-aligned, so counting causes no layout shift (an e2e test measures under 0.01).
  - **Target size:** inline receipts and the inline demo link carry `data-inline-target` and are exempt from the 44 px rule under WCAG 2.5.8. Every other receipt is at least 44 × 44 px.
- **ADR-022 Grove role switch: a native radio group over a pure rules function.**
  - **Rules:** `src/lib/permissions-demo.ts` applies own/team/all scopes per field to fictional people in `src/content/roleDemo.ts`. Offboarded records are HR-only. Seven unit tests pin the rules.
  - **UI:** a fieldset of radios (arrow keys move between roles; no Radix ToggleGroup needed), a real `<table>` in a focusable scroll region on phones, and a `role="status"` line that announces each change ("As Manager: 4 of 5 people shown, 8 fields restricted."). Restricted cells say "Restricted" with a lock icon, never colour alone.
  - **Copy:** labelled as an illustration with made-up people, with the line "Enforced on the server, not hidden in the UI." and a link to the real live demo. Nothing animates.
  - **Content check:** the content test allows numbers from `facts.ts` plus this labelled demo data.

- **ADR-023 Case studies are explicit static routes, not `/work/[slug]`.** With Cache Components on, an unknown `[slug]` renders at request time and the static shell has already started streaming when `notFound()` runs, so Next answers **200** with a `noindex` tag (documented behaviour). The documented fix is a Proxy check, which would put a server function in front of every case-study request. Instead each project has a three-line route file (`src/app/work/<slug>/page.tsx`) that renders the shared `CaseStudyPage`. An unknown `/work/...` matches no route and gets a real **404** with zero runtime. A unit test keeps the route folders and `facts.projects` in sync, and an e2e test asserts the 404.
- **ADR-024 Architecture diagrams are semantic HTML with SVG arrows.** The brief asks for inline SVG diagrams with `<title>`/`<desc>`. Text inside an SVG cannot reflow: at 320 px or 200% zoom it would shrink below legibility (WCAG 1.4.4, 1.4.10). So each diagram is a `<figure>` whose layers form an ordered list, with the description as the `<figcaption>`. Only the arrows are SVG, and they are `aria-hidden`. The data lives in `facts.ts` (`caseStudy.diagram.layers`), so all three diagrams share one component.
- **ADR-025 The skip link focuses the visible `<main>`.** With Cache Components, Next keeps up to three visited routes in the DOM, hidden with `display: none` (React Activity). After a client-side navigation there are several `<main id="main">`, and `#main` can resolve to a hidden one. The skip link now focuses the first visible `<main>` (`checkVisibility()`). Without JavaScript there is only one main, and the plain anchor works. An e2e test navigates home → case study and checks that focus lands on the visible page. Tests that look for headings use roles, which ignore the hidden routes.
- **ADR-026 Long metrics step down a size.** "0.495 → 0.004" wrapped onto three lines at numeral size. Displays over 6 characters now use the next size down, take a full row and never wrap.
- **Count-up digits carry their own underline.** Text decoration does not propagate into inline-blocks, so the counting numerals had lost the dotted cue that marks a receipt. An e2e test now checks every receipt for an underline.

- **ADR-027 SEO and sharing, all static.**
  - **Share images:** `next/og` renders a share card for the site and one per case study from a single renderer (`src/lib/og-image.tsx`). It uses the paper palette, Newsreader and Plex Sans read from `@fontsource` WOFF files at build time (no network), and the flow lines faded in from the left.
  - **Metadata:** Open Graph and Twitter (`summary_large_image`), and a canonical link on every page.
  - **Person JSON-LD:** only `name`, `jobTitle`, `url` and `sameAs` (LinkedIn, GitHub). An e2e test checks it holds no email or phone.
  - **Sitemap and robots:** `sitemap.xml` lists `/` and the three case studies; `robots.txt` disallows `/design`, which is also `noindex`.
  - **Résumé:** `/resume` is a temporary (307) redirect to the PDF once it exists, and to LinkedIn until then.
  - **404:** a custom page inside the normal layout. Unknown URLs get a real 404 status, and it is in the axe matrix.
  - **Caveat:** canonical, Open Graph and sitemap URLs use `http://localhost:3000` until the domain is confirmed (open item 1), and the ship gate fails until then.
- **ADR-028 Case-study IDs carry the project slug.** This extends ADR-025. When one case study links to the next, the previous page stays hidden in the DOM. Shared IDs (`architecture-title`, `problem-title`) let the visible page's `aria-labelledby` resolve to the hidden page's heading, so LeadHub's diagram could be announced with Grove's title. Section and diagram IDs are now `<slug>-…`. An e2e test moves Grove → LeadHub and checks the figure's accessible name, and that no ID repeats except the layout's `main`.

- **ADR-029 Hosted on GitHub Pages as a static export, at the owner's request.** The site is `https://rrushikeshp89.github.io`; the repository was renamed to `rrushikeshp89.github.io` so it serves from the root, with no base path and no link rewriting. `next.config.ts` sets `output: "export"` and `trailingSlash: true`, and CI publishes `out/` with `actions/deploy-pages` only after a push to `main` passes every check. What changed, and why:
  - **No response headers on Pages.** The Content-Security-Policy moved to a `<meta http-equiv>` tag (`src/lib/csp.ts`) with the same directives except those a meta policy cannot carry. Lost on this host: `frame-ancestors`, `X-Frame-Options`, `Permissions-Policy`, `Cross-Origin-Opener-Policy` and our own HSTS (github.io itself enforces HTTPS). The referrer policy is a `<meta name="referrer">`. e2e now checks the meta policy on every page type, and that it blocks a script from another origin.
  - **No server redirects.** `/resume/` is a static page that forwards with a meta refresh and links to the same place: the PDF once it exists, LinkedIn until then.
  - **Cache Components is off.** Static export requires `dynamic = "force-static"` on metadata routes, and Cache Components forbids that setting. A site with no data to cache gains nothing from it. ADR-025 and ADR-028 stay in place: they are harmless without it and protect against any future route preservation.
  - **Share images are real `.png` files.** The `opengraph-image` convention exports extensionless files, which Pages would serve as `application/octet-stream`. They are now `og.png` route handlers (`/og.png`, `/work/<slug>/og.png`) wired into the metadata.
  - **Tested as served.** `scripts/serve-static.mjs` mimics Pages: it gzips text, resolves directories to `index.html`, sends a 301 to add a missing trailing slash, and serves `404.html` with status 404. Playwright, Lighthouse and the bundle check all run against `out/` through it. (A first version sent uncompressed text and pushed local LCP to 1.5 s; with gzip it is back to 0.91 s.)
  - **A test fix found along the way:** the receipt close-button test was flaky (1 in 4) because it clicked during the slip's 160 ms entrance animation and hit the backdrop. It now waits for the animation, as a person effectively does.

- **ADR-030 The résumé PDF is generated from `facts.ts` at build time.** The PDF the owner supplied contained the phone number (which they chose not to publish), the old email address and two facts the site had since corrected. Rather than publish a second, drifting source, `pnpm build` now runs `next build`, then `scripts/build-resume.mjs`, which prints `/resume/document/` to `out/resume.pdf` with Playwright (A4, light theme, print styles).
  - **The document page:** a `noindex` HTML résumé built only from `facts.ts`: name, role and location; email, site, LinkedIn and GitHub (no phone); objective; projects first, then experience, education and certifications, and skills.
  - **The script fails the build** if the page contains a phone number or does not fit one A4 page. The first draft ran to two pages; tightening 9.5 pt to 9 pt type fixed it.
  - **Linked everywhere:** the header's Résumé link, the "Download résumé (PDF)" button and `/resume/` all point to `/resume.pdf`.
  - **Print styles:** site chrome is hidden, and the palette is pinned to ink on white whatever the screen theme.
  - **On screen:** the page is in the axe matrix. Its contact links get 24 px targets with row spacing (WCAG 2.5.8), and print keeps the compact layout.
  - With no `TODO(confirm)` left, `pnpm test:ship` now runs in CI.
  - **Static Plex Sans for clean print on Linux.** The first CI-built PDF mis-spaced letters in medium-weight text ("Dat abases", "Securit y"), a Chromium-on-Linux PDF issue with variable fonts that did not show on Windows. Google serves Plex Sans as a variable font even when weights are named, so the site now loads static 400 and 500 cuts from `@fontsource/ibm-plex-sans` through `next/font/local`. Cost: about 6 kB more font data (88 kB total); the PDF dropped from 132 kB to 40 kB.

- **ADR-031 "Email me" opens an email options panel.** A `mailto:` link only hands off to the visitor's registered mail app. On machines without one set up (the owner's included, and common for people who use webmail), a click does nothing visible. Both email triggers (the hero's "Email me" and the address in Contact) stay real `mailto:` links, so they still work without JavaScript. With JavaScript, a click opens a native modal slip (the receipts' pattern: focus trapped, Esc and Close dismiss it, focus returns, anchored where supported) offering:
  - **Copy email address,** with a `role="status"` confirmation, and the address spelled out if the clipboard is blocked.
  - **Write in Gmail** and **Write in Outlook.com:** pre-addressed compose links in a new tab, announced as such.
  - **Open my mail app:** the original `mailto:`.
  - **Why not a contact form:** no third party sees anything unless the visitor picks Gmail or Outlook, so there is no form service, key, spam handling or privacy note to maintain (ADR-007 stands).
  - **Cost and checks:** +0.6 kB of JS. e2e covers the `mailto:` fallback, every action's link, a real clipboard copy, Esc and focus return, the Contact trigger, and axe on the open panel.

- **ADR-032 The headline emphasises "full-stack TypeScript", at the owner's request.** The phrase is set in Newsreader italic in the accent colour (7.5:1 in light; the dark accent passes the token contrast tests). frontend-design advises against accenting one phrase of a headline, but the owner asked for it with a reference image, and the brief's own words win on visual direction.
  - **Data:** the phrase is `identity.headlineEmphasis` in `facts.ts`, and the schema fails the build unless it occurs in `headline`. The plain headline still feeds titles, share cards and JSON-LD.
  - **Layout:** from 1280 px the `h1` spans the full width at 4.25 rem and breaks before the phrase, giving the reference's two lines (line 1 needs about 1,068 px of the 1,088 px column). Narrower screens wrap naturally.
  - **Fonts:** the italic is now preloaded, because it is above the fold.
  - **Measured:** the first local Lighthouse runs after this change failed (85–92). An A/B on the same machine showed the build _without_ the change also failing (87 / 87) and the build with it passing (97 / 99), so the dip was host noise, not the change.

## UX review of the home page (Phase 3)

- **Recruiter, 30 s.** Above the fold at 1280 × 800: role (h1), stack (sub-line), location and intent ("open to Software Developer roles"), Email me. At 375 × 812, the same plus both CTAs within thumb reach. Gap: no résumé link until the PDF exists (open item 4).
- **Engineering manager.** Each project has source and live links whose names make sense out of context, the stack as plain text, and the strongest three bullets. The receipts (Phase 4), case studies (Phase 5) and limitations (Phase 5) are still to come, and they are what this persona needs most.
- **Order check.** Work comes before Experience, and the 15% Zetpeak result sits in the Experience margin so it is the first thing seen there. The copy "every project states what it does not do yet" becomes true only when Phase 5 fills the limitations; the ship gate fails until then.
